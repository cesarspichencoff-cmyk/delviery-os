## CASE-PROT-01 — Item faltante após a saída

| Campo | Conteúdo |
|---|---|
| **Base** | CASE-L8-O01 |
| **Formação** | F2 |
| **Funções** | SAC · Caixa · (produção se investigação) · LE se $ |
| **Competências** | C-SAC01–04 · C-CX04 |
| **Protocolos** | P2 · P6 tipos |

### Contexto
Pedido já saiu pelo canal. Cliente contata: faltou um item do combinado. Horário: pós-pico leve (21h). Equipe ainda na loja.

### Informação disponível
- Relato do cliente (item X faltando).  
- Pedido consta como saído.  
- SAC está no canal.  
- Regra $ provisória: qualquer desconto/voucher/estorno comercial exige liderança.

### Informação ausente
- Foto do cliente.  
- Confirmação se item saiu da montagem.  
- Comanda física à mão no primeiro segundo.  
- Se foi erro de rota ou de montagem.

### Opções (escolha)
| # | Opção | Risco |
|---|---|---|
| A | Oferecer desconto imediatamente no chat e encerrar. | $ sem A; sem investigação; fecha errado |
| B | Pedir desculpas, prometer “resolver amanhã” sem dono nem horário de retorno. | Ciclo aberto; frustração |
| C | Reformular o relato; declarar o que já sabe (saiu; item alegado); iniciar checagem comanda/expedição; informar retorno em X min; **se** $ , escalar LE; registrar; acompanhar até fechar. | Tempo no pico residual; exige disciplina de fechamento |
| D | Dizer que só resolve com foto; se cliente não mandar, encerrar sem mais passos. | Pode ser **parcialmente** útil pedir evidência, mas encerrar só por isso abandona o ciclo |

### Princípio
Percepção do cliente é real para a relação; **causa** só com fato. Fechar o ciclo com dono. $ com liderança.

### Resposta recomendada
**C** (D pode complementar **dentro** de C: pedir evidência sem usar como desculpa para sumir).

### Razão
Preserva investigação, propriedade SAC, regra $ e encerramento.

### Ação posterior
Registrar tema omissão (categoria); se padrão, P12 leve — **sem** nomear pessoa em público.

### Evidência possível
Nota &lt;1 min: fato · passo · se $ autorizado · status aberto/fechado.

### Contestação
Se alguém registrar “funcionário X esqueceu” sem fato → contestável; status não consolidado.

## CASE-PROT-02 — Pico, “cadê?” e escalonamento sem contexto

| Campo | Conteúdo |
|---|---|
| **Base** | CASE-L8-E01 (+ pico A01) |
| **Formação** | F1 |
| **Funções** | DJ/DP/DS · AO · LE |
| **Competências** | C-T03 · C-DS03/C-DS04 |
| **Protocolos** | P10 · P8 essencial |

### Contexto
19h. Volume alto. Várias sacolas na bancada. Alguém grita para Quentes: “Cadê?” Pressão verbal sobe. Um pedido simples está quase completo; um multi-praça trava a fila.

### Informação disponível
- Horário de pico.  
- Há pedidos aguardando na bancada (quantidade aproximada visível).  
- Prioridade oficial: (1) mais próximo de conclusão (2) gargalo multi (3) mais antigo com risco (4) qualidade/segurança (5) fluxo global.  
- Pressão verbal **não** define prioridade.

### Informação ausente
- ETA exato da praça.  
- Se o grito se refere a qual pedido.  
- Capacidade real de Quentes neste minuto.

### Opções
| # | Opção | Risco |
|---|---|---|
| A | Repetir “cadê?” mais alto até alguém largar o que está fazendo. | Caos; qualidade; prioridade errada |
| B | Parar a praça inteira para “alinhar moral”. | Piora o fluxo global |
| C | Nomear estado (ex.: 3 aguardam Quentes), impacto (expedições paradas), ação (previsão / se precisa reforço); aplicar 5 critérios (ex.: liberar o quase pronto se não depender do gargalo). | Exige 20–40 s de clareza |
| D | Só empurrar o multi-praça “porque é o mais antigo” sem ver o que está quase pronto. | **Parcialmente** alinhado ao critério 3, ignora 1 e 2 |

### Princípio
Estado + impacto + ação. Prioridade por raciocínio, não por volume da voz.

### Resposta recomendada
**C** (D é parcialmente correta se o antigo tem risco real **e** nada está mais perto de fechar).

### Razão
Transforma pressão em decisão e protege fluxo.

### Ação posterior
Se gargalo persiste, escala LE com o mesmo esqueleto de mensagem.

### Evidência possível
Observação de uma comunicação com 3 elementos no pico (amostra).

### Contestação
Se validador marcar “não escalou” sem ver que a pessoa estava na praça correta com estado claro → contestável.

## CASE-PROT-03 — Colaboração com responsabilidade preservada (positivo)

| Campo | Conteúdo |
|---|---|
| **Base** | CASE-L8-B01 (+ traços B03) |
| **Formação** | F1 |
| **Funções** | DJ · DP · DS |
| **Competências** | C-T02 · C-DJ03 |
| **Protocolos** | P5 |

### Contexto
Pico. Dono da sacola (posição) está com dois pedidos. Colega ajuda a montar. Kit e lacre ainda pendentes. Expedição se aproxima.

### Informação disponível
- Dono designado no pré-turno.  
- Ajuda espontânea do colega.  
- Pedido ainda na loja.

### Informação ausente
- Se o dono quer transferir de vez.  
- Se o colega assume até o fim.

### Opções
| # | Opção | Risco |
|---|---|---|
| A | Colega termina sozinho e some; dono assume que “alguém fechou”. | Omissão / sem dono |
| B | Dono grita “não me ajuda” e trava a colaboração. | Protege ego; perde capacidade |
| C | Colega pergunta “fecho o kit com você ou você assume?”; dono responde **explicitamente** (mantém ou transfere); kit conferido por quem fecha; comunicação breve se multi-sacola. | 10 s de alinhamento |
| D | Os dois conferem em silêncio sem dizer quem é o dono — “tá todo mundo vendo”. | **Parcialmente** melhor que A; ainda ambíguo sob pressão |

### Princípio
Ajuda com responsabilidade. Qualidade antes da pressa. Transferência explícita.

### Resposta recomendada
**C** (D é parcial se ambos de fato conferem, mas C escala melhor).

### Razão
Colaboração + propriedade + qualidade.

### Ação posterior
Reconhecer no Passaporte como evidência **positiva** (não só falhas).

### Evidência possível
“Ajudou na montagem; confirmou dono em voz alta; kit conferido antes de grampear.”

### Contestação
Se alguém registrar só a falha de outro turno e ignorar este ato positivo de forma tendenciosa no dossiê → LE/César corrige mix (anti-punição).
