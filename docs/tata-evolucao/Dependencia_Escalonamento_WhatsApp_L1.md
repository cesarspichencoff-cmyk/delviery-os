# Dependência e Escalonamento — WhatsApp L1

> Mapeia **tipos de dependência de autoridade**, não avalia quem pergunta.  
> Métricas = mensagens/unidades com sinais de consulta ou presença do hub — **heurística**.

---

## 1. Sinais observados (agregados)

| Sinal | Ordem de grandeza L1 |
|---|---|
| Unidades com marca de escalonamento/consulta | ~4.1k (superconjunto amplo) |
| Unidades ligadas a liderança/staffing | ~1.1k |
| Unidades com compensação (muitas exigem autorização) | ~0.85k |
| Mensagens não-sistema do papel `authority_hub` | concentradas (um canal sozinho ~40% do volume total de msgs) |

Interpretação cautelosa: o hub **participa** de muitos canais; isso prova centralidade de comunicação, não “erro” de quem pergunta.

---

## 2. Classes de dependência (taxonomia operacional)

| Classe | Definição | Exemplo genérico | Vira o quê |
|---|---|---|---|
| **consulta_necessaria** | Exige autoridade real (risco, exceção, valor alto) | Compensação atípica | Manter escalonamento |
| **consulta_regra_ausente** | Ninguém sabe a regra escrita | “Como montamos X agora?” | Documento + treino |
| **consulta_autonomia_indefinida** | Cargo poderia decidir, mas limite não está claro | “Posso recusar cortesia?” | Matriz de autonomia |
| **consulta_repetitiva** | Mesma dúvida em vários períodos | Kit/pausa/fechamento | FAQ / microtreino |
| **consulta_situacao_excepcional** | Caso raro | Falha grave de sistema | Playbook de crise |
| **consulta_sem_resposta_documentada** | Pergunta no export sem resposta visível | — | Risco; pode haver resposta oral |
| **decisao_concentrada** | Decisões de turno passam pelo mesmo hub | Pausas, prioridades | Redistribuir com desenho |

## 3. Conhecimentos que o escalonamento revela (oportunidades)

| Conhecimento embutido na pergunta | Artefato candidato |
|---|---|
| Critério de cortesia | Regra / matriz de compensação |
| Quando pausar item | Procedimento + sinal de disponibilidade |
| Ordem de prioridade de produção | Briefing de liderança |
| O que conferir antes de lacrar | Checklist de conferência |
| Como agir se impressora falha | Contingência de caixa |
| Quem cobre escala | Processo de escala (RH/liderança) |
| Como falar com cliente em atraso | Script de atendimento (limites) |

---

## 4. Classificação de qualidade do escalonamento (para treino)

Rubrica **futura** (não aplicada pessoa a pessoa na L1):

1. Trouxe **fato** (pedido/sintoma)?  
2. Disse o que **já tentou**?  
3. Indicou **impacto** (cliente/tempo/custo)?  
4. Propôs **opção**?  
5. Era **hora** adequada (pico vs pós)?  

Uso: ensinar a **forma** da consulta, não ranquear pessoas.

---

## 5. Hipótese (não meta)

Reduzir **consultas repetitivas por regra ausente** via Academia e procedimentos deve diminuir ruído no hub — **só medível** com baseline de tipos (não de volume bruto de mensagens).

---

## 6. O que não fazer

- Dizer que “a equipe é dependente demais” como julgamento moral.  
- Usar contagem de menções ao hub como score individual.  
- Automatizar alerta “fulano perguntou de novo”.  

---

*Escalonamento como design de conhecimento · sem avaliação de pessoas.*
