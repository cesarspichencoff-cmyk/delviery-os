## Decisão de arquitetura Radar Toqan
**Manter como sensor complementar não autoritativo**, não como segunda IA controladora. Toqan é indicado para tendências/cancelamentos/atrasos agregados e comparação de períodos, nunca para GPS, item real, pedido curto/UUID, pronta-entrega ou execução da operação. Não confundir `despachado` do iFood/Toqan com status de produção física. O Copiloto só pode citar números com data, período, loja, granularidade e fonte verificados.

Termos públicos do Toqan para Restaurantes proíbem robôs/crawlers/coleta automatizada e engenharia reversa; portanto **não criar scraper, CDP, extensão, cookies ou API privada para extrair dados do Toqan**. Usar somente funcionalidade nativa, exportação/manual legítima quando disponível e autorizada ou interface oficial que o provedor explicitamente permita; verificar também se o uso dos dados em ferramenta externa é autorizado. O adaptador é uma estrutura pronta para recebimento futuro, não evidência de existência de export nativo. Links: https://restaurantes.toqan.ai/ ; https://restaurantes.toqan.ai/legal/terms-and-conditions .

### Contrato do adaptador
`tools/toqan-radar-shadow/adapter.cjs` é função pura sem rede/ações. Entrada deliberadamente estreita: `TOQAN`, `MANUAL_EXPORT` ou `PROVIDER_AUTHORIZED_EXPORT`, escopo Itaim, período com fuso SP, data de geração, métricas numéricas permitidas (pedidos, atrasados, cancelados, despachados, tempo médio de preparo e pausas). Campos adicionais, PII, loja errada e proporções impossíveis produzem HOLD. A saída é `SHADOW_AGGREGATE_REVIEW_ONLY`, `realTime=false`, `orderLevel=false`, `sourceIndependentlyVerified=false`, `gps=false`, `canTriggerAction=false`, sem dedução de zero para métrica ausente. `node tools/toqan-radar-shadow/adapter.test.cjs` deve repetir 32/32.
